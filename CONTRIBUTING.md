# Contributing to Kikar AI

Thank you for your interest in **Kikar AI**! 

Kikar is an active, proprietary commercial platform that provides AI persona simulation, real-time messaging, offline digital replicas, and anonymous stranger matchmaking with AI wingman assistance.

To maintain strict intellectual property ownership, code integrity, and legal clarity for commercial operations, we follow the contribution guidelines outlined below.

---

## 🚫 External Code Pull Requests (Closed)

**We do not accept unsolicited external code Pull Requests at this time.**

All production code, core architecture, and algorithms are developed and maintained directly by the project owner (**Bhavya Sharma / Kikar AI**). 

### Why this policy exists:
- **Clean Copyright Ownership**: As a commercial platform with billing tiers and paid services, we avoid third-party copyright claims or licensing ambiguities.
- **Product Vision & Security**: Direct messaging, authentication, user replica generation, and billing pipelines require tight architectural control and rigorous security vetting.

Any pull requests submitted without prior written agreement will be closed without review.

---

## 💡 How You CAN Contribute

While direct code contributions are closed, community feedback is invaluable! Here is how you can help make Kikar better:

### 1. Reporting Bugs & Issues
Found a bug, glitch, or unexpected behavior?
- Check the [GitHub Issues](https://github.com/Bhavya4907/Kikar/issues) tab to see if the issue has already been reported.
- If not, open a new **Bug Report** including:
  - A clear and descriptive title.
  - Device and environment details (e.g., *Android APK, Chrome 120 on Windows 11, iOS Safari*).
  - Step-by-step instructions to reproduce the issue.
  - Expected vs. actual behavior (screenshots or screen recordings are appreciated).

### 2. Suggesting Features & UX Improvements
Have an idea for a new vibe slider, chat feature, or UI enhancement?
- Open an issue labeled **`enhancement`** or **`feature-request`**.
- Describe the problem your suggestion solves and how you envision the user experience.

### 3. Reporting Security Vulnerabilities
If you discover a security vulnerability (especially regarding user authentication, database RLS policies, private direct messages, or payment webhooks), **do not open a public GitHub issue**.
- Please refer to our [Security Policy](./SECURITY.md) and email us privately at **`bhavya497sharma@gmail.com`**.
